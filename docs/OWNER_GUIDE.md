# Руководство владельца INSIDA

Это руководство для человека без опыта программирования. Код писать не нужно: вы будете копировать команды и вставлять их в терминал. У каждого шага есть **«Ожидаемый результат»**. Если он не совпадает, остановитесь и посмотрите раздел «Если что-то пошло не так» в конце.

> **Терминал** — окно для текстовых команд. На Windows это «PowerShell» (Пуск → набрать PowerShell), на Mac — «Терминал» (Программы → Утилиты). Команду вставляйте целиком и нажимайте Enter.

---

## 1. Что установить

1. **Node.js 22 LTS** — https://nodejs.org (кнопка LTS). Устанавливайте с настройками по умолчанию.
2. **Visual Studio Code** — удобный редактор файлов: https://code.visualstudio.com
3. **Docker Desktop** — запускает базу данных на компьютере одной командой: https://www.docker.com/products/docker-desktop
   *(Альтернатива без Docker — установить PostgreSQL 16 с https://www.postgresql.org/download/.)*
4. **GitHub Desktop** — понадобится для публикации: https://desktop.github.com

Проверьте в терминале:

```bash
node -v
npm -v
docker -v
```

**Ожидаемый результат:** три строки с номерами версий, например `v22.…`, `10.…`, `Docker version …`.

## 2. Как открыть проект

1. Распакуйте архив `insida.zip` в удобную папку, например `Документы/insida`.
2. Откройте VS Code → **File → Open Folder** → выберите папку `insida`.
3. Откройте встроенный терминал: **Terminal → New Terminal**. Он сразу откроется в папке проекта.
4. Установите зависимости (один раз, займёт 1–3 минуты):

```bash
npm install
```

**Ожидаемый результат:** в конце строка вида `added 400 packages` и нет красных слов `ERR!`.

## 3. Как создать базу данных

Запустите Docker Desktop (дождитесь зелёного статуса «Running»), затем:

```bash
docker compose up -d
```

**Ожидаемый результат:** `Container insida-db-1 Started`. Это ваша локальная база на компьютере — данные хранятся только у вас.

## 4. Как настроить переменные окружения

Переменные окружения — это «секретные настройки» сайта. Они лежат в файле `.env`, который **никому нельзя отправлять**.

```bash
cp .env.example .env
```
*(На Windows, если команда не сработала: `copy .env.example .env`.)*

Сгенерируйте секрет:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
```

Откройте файл `.env` в VS Code и вставьте полученную строку после `AUTH_SECRET=`. Сохраните (Ctrl+S / Cmd+S). Остальное менять не нужно.

**Ожидаемый результат:** в `.env` строка `AUTH_SECRET=` заканчивается длинной случайной строкой.

## 5. Как запустить локально

```bash
npm run db:migrate
npm run db:seed
npm run dev
```

**Ожидаемый результат:**
- после первой команды — `✓ База данных в актуальном состоянии`;
- после второй — `✓ Демо-наполнение создано`;
- после третьей — `Local: http://localhost:3000`.

Откройте в браузере **http://localhost:3000** — вы увидите главную страницу INSIDA. Остановить сайт: в терминале нажмите `Ctrl+C`.

## 6. Как создать администратора

Откройте второй терминал (кнопка «+» в панели терминала) и выполните:

```bash
npm run admin:create
```

Введите имя (например, `Вика`) и пароль не короче 10 символов. Пароль при вводе не отображается — это нормально.

**Ожидаемый результат:** `✓ Администратор «Вика» создан` и **8 кодов восстановления**.
⚠️ **Сохраните коды** (распечатайте или положите в менеджер паролей). У аккаунта нет e-mail, поэтому коды — единственный способ восстановить доступ через сайт.

Теперь откройте **http://localhost:3000/login**, войдите — откроется админ-панель.

## 7. Как опубликовать сайт бесплатно

Схема: **Neon** (база данных) + **GitHub** (хранит код) + **Netlify** (показывает сайт).
Перед этим прочитайте [чек-лист запуска](LAUNCH_CHECKLIST.md): там ограничения бесплатных тарифов и юридические шаги.

### 7.1. База данных в Neon
1. Зарегистрируйтесь на https://neon.com (бесплатный план Free).
2. Создайте проект: имя `insida`, Postgres 16, регион — ближайший к читателям из Европы (например, Frankfurt).
3. На странице проекта нажмите **Connect**, выберите вариант **Pooled connection** и скопируйте строку вида
   `postgresql://…@…-pooler.….neon.tech/neondb?sslmode=require`.

**Ожидаемый результат:** у вас есть строка подключения. Это тоже секрет.

### 7.2. Наполнить облачную базу (с вашего компьютера)
Временно подставьте облачную строку и выполните команды. На Mac/Linux:

```bash
DATABASE_URL="ВСТАВЬТЕ_СТРОКУ_NEON" npm run db:migrate
DATABASE_URL="ВСТАВЬТЕ_СТРОКУ_NEON" npm run db:seed
DATABASE_URL="ВСТАВЬТЕ_СТРОКУ_NEON" npm run admin:create
```

На Windows (PowerShell):

```powershell
$env:DATABASE_URL="ВСТАВЬТЕ_СТРОКУ_NEON"; npm run db:migrate; npm run db:seed; npm run admin:create
```

**Ожидаемый результат:** те же сообщения, что в шагах 5 и 6. Сохраните новые коды восстановления: это уже администратор боевого сайта.

### 7.3. Код на GitHub
1. Зарегистрируйтесь на https://github.com.
2. В GitHub Desktop: **File → Add local repository** → выберите папку `insida` → согласитесь создать репозиторий.
3. Нажмите **Publish repository** и **оставьте галочку «Keep this code private»**.

**Ожидаемый результат:** проект виден в вашем аккаунте GitHub как приватный репозиторий. Файл `.env` туда не попадает: он исключён настройками проекта.

### 7.4. Сайт на Netlify
1. Зарегистрируйтесь на https://www.netlify.com через GitHub (бесплатный план Free).
2. **Add new project → Import an existing project → GitHub** → выберите `insida`.
3. Настройки сборки подтянутся из файла `netlify.toml` — ничего не меняйте.
4. Перед запуском откройте **Environment variables** и добавьте:

   | Ключ | Значение |
   |---|---|
   | `DATABASE_URL` | строка Neon из шага 7.1 |
   | `AUTH_SECRET` | **новая** случайная строка (сгенерируйте как в шаге 4) |
   | `SITE_URL` | `https://ВАШЕ-ИМЯ.netlify.app` (адрес можно узнать или поменять после первой публикации) |
   | `TRUSTED_PROXY_COUNT` | `1` |
   | `DB_POOL_MAX` | `3` |

5. Нажмите **Deploy**. Через 2–4 минуты сайт будет доступен по адресу `https://….netlify.app`.
6. Если вы меняли имя сайта (Site configuration → Change site name), обновите `SITE_URL` и нажмите **Deploys → Trigger deploy**.

**Ожидаемый результат:** сайт открывается по адресу Netlify, вход в админку — `/login`.

Дальше каждое изменение кода, отправленное через GitHub Desktop (**Commit** → **Push origin**), публикуется автоматически.

## 8. Как добавлять статьи и тесты

Всё делается в админ-панели (`/login`), код трогать не нужно.

**Статья:** Админ-панель → «Статьи и термины» → «+ Новый материал».
1. Заголовок (адрес страницы заполнится сам).
2. Краткое описание и текст. Текст пишется в формате Markdown: `## Подзаголовок`, `**жирный**`, `*курсив*`, `- пункт списка`, `> цитата`. Кнопка «Предпросмотр» показывает, как это будет выглядеть.
3. Источники — по одному в строке: `Название | https://ссылка | примечание`. Указывайте только реальные источники.
4. Справа: тема, теги, обложка, автор, дата обновления, статус проверки.
5. «Сохранить» — черновик (на сайте не виден), «Опубликовать» — материал появится на сайте.
6. Снимите галочку «Демонстрационный материал», если это ваш настоящий текст.

**Тест:** «Тесты» → «+ Новый тест».
1. **Шкалы** — что вы измеряете (например, «Самокритика»). Ключ шкалы пишется латиницей.
2. **Вопросы** — кнопка «+ Вопрос» сразу добавляет варианты «Почти никогда … Почти всегда» с баллами 0–4. Баллы можно менять в окошках справа от варианта.
3. **Ветвление** (необязательно): в поле «→ №» у варианта укажите номер вопроса, к которому нужно перейти.
4. **Правила результатов**: для каждой шкалы задайте диапазоны баллов («от–до») и бережные описания. После сохранения админка предупредит, если какой-то балл не попадает ни в одно правило.

⚠️ Не называйте опросник диагностикой. Не публикуйте известные клинические шкалы без проверки лицензии и правил интерпретации.

**Практики, программы, книги, гайды, FAQ, страницы** устроены так же: раздел в меню слева → «+ Новый…».

## 9. Как менять фото, тексты и цвета

- **Фото:** «Медиафайлы» → загрузите изображение (JPG/PNG/WebP до 4 МБ). Скопируйте адрес `/media/…` и вставьте в поле «Обложка» материала или в «Настройки сайта» (фото первого экрана, фото основателя). Сжимайте фото до ~1600 px по ширине, например на https://squoosh.app. Используйте только фото, на которые у вас есть права.
- **Тексты главной, «Об INSIDA», контакты, соцсети, реквизиты продавца:** «Настройки сайта».
- **Документы (политика, условия, оферта):** «Страницы и документы».
- **Цвета и шрифты:** откройте в VS Code файл `src/styles/tokens.css`. Все цвета собраны в начале файла, например `--c-rose: #c99fa7;`. Замените HEX-код, сохраните — при `npm run dev` изменения видны сразу. Чтобы они появились на опубликованном сайте, отправьте изменения через GitHub Desktop (Commit → Push). Проверяйте контраст текста, например на https://webaim.org/resources/contrastchecker/ (нужно не меньше 4.5:1).

## 10. Резервные копии и обновление проекта

**Резервная копия базы.** Нужна утилита `pg_dump` (ставится вместе с PostgreSQL; на Mac: `brew install libpq`).

```bash
DATABASE_URL="СТРОКА_NEON" npm run backup
```

**Ожидаемый результат:** `✓ Резервная копия: backups/insida-ДАТА.dump`. Делайте копию раз в неделю и перед крупными изменениями; храните её не только на этом компьютере (например, в облаке). Хранятся 14 последних копий.

Восстановление (заменит данные в базе!):

```bash
DATABASE_URL="СТРОКА_NEON" npm run restore -- backups/insida-ДАТА.dump
```

Кроме того, на бесплатном плане Neon можно откатить базу на несколько часов назад в панели Neon (раздел Restore). Это работает только для недавних изменений, поэтому собственные копии всё равно нужны.

**Обновление зависимостей** (раз в 1–3 месяца):

```bash
npm outdated
npm update
npm test
npm run build
```

**Ожидаемый результат:** тесты проходят (`Tests … passed`), сборка завершается без ошибок. После этого отправьте изменения через GitHub Desktop: Netlify опубликует их сам.

## Если что-то пошло не так

| Что видите | Что делать |
|---|---|
| `command not found: npm` | Node.js не установлен — шаг 1, перезапустите терминал |
| `ECONNREFUSED … 5432` | База не запущена: откройте Docker Desktop, затем `docker compose up -d` |
| `relation … does not exist` | Выполните `npm run db:migrate` |
| `AUTH_SECRET не задана` | Шаг 4 |
| `Неверный псевдоним или пароль` | Проверьте раскладку; после 8 ошибок вход блокируется на 15 минут |
| Забыли пароль | `/recover` и код восстановления, или `npm run admin:reset-password` с облачной `DATABASE_URL` |
| Сборка на Netlify упала | Netlify → Deploys → откройте лог; чаще всего не задана переменная `DATABASE_URL` |
| Сайт показывает «Site not available» | Кончились бесплатные кредиты Netlify за месяц — см. чек-лист |

Подробнее для разработчика — в [README](../README.md).
